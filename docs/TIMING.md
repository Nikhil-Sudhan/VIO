# Timing and frame contract under development

Raw input is authoritative. `raw.jsonl` holds each original 7-byte FIFO word (tag plus six payload bytes), status snapshots, read intervals, and periodic four-byte clock reads. Camera `SensorTimestamp` is preserved verbatim with receipt times, request sequence and full metadata. Derived CSV is reproducible from raw input. No gap filling or guessed calibration is permitted.

ST AN5272 sections 9.4/9.5 define the two-bit slot counter and the timestamp belonging to that FIFO time slot. We use equal gyro/accel batch rates, no compression, and timestamp decimation one. Decode requires a timestamp and exactly one of each sensor with the same slot counter; validate even tag parity and timestamp BDR metadata. The slot counter wraps every four slots and is NOT a full sample counter. Timestamp gaps and FIFO flags are also necessary for detecting loss. Incomplete stop-boundary groups are explicitly counted and trimmed.

The nominal sensor tick is 25 us, but the first host-clock fit measured ~25.52 us. Map sensor ticks to Pi BOOTTIME using captured read brackets and a recorded affine fit; a long run must establish drift/temperature dependence. The bracket midpoint is a clock observation, not the IMU measurement timestamp. Internal filtering and FIFO batching introduce delay not bounded by the fit residual. Camera/IMU time offset still requires physical calibration. Reference: [ST AN5272](https://www.st.com/resource/en/application_note/dm00571818-lsm6dsox-alwayson-3d-accelerometer-and-3d-gyroscope-stmicroelectronics.pdf).

The generic libcamera API describes SensorTimestamp as first-row exposure time in BOOTTIME, but that definition alone does not establish this driver's behavior. Source matching installed libcamera tag `v0.7.2+rpt20260817`, `src/libcamera/pipeline/rpi/pisp/pisp.cpp:1767`, copies the CFE buffer timestamp unchanged. No exposure-midpoint correction is present there. The installed kernel package changelog identifies Linux commit `60ea684a8ace97bb0db1a16e20753bdd6ab371ff`. Its CFE source uses `ktime_get_ns()` in the frame-start handler and marks buffers MONOTONIC; the matched source has been saved as `evidence/kernel-cfe-60ea684.c`. BOOTTIME and MONOTONIC currently agree to microseconds because no suspend occurred. Record both, reject a suspend discontinuity, and do not relabel a frame-start interrupt as exposure midpoint. Source snapshots are retained in `evidence/`. [libcamera control reference](https://docs.libcamera.org/master/internal-api/namespacelibcamera_1_1controls.html), [Raspberry Pi libcamera source](https://github.com/raspberrypi/libcamera/tree/v0.7.2%2Brpt20260817).

IMX219 is rolling shutter. OpenVINS camera observations use one time per image; this integration does not model per-row readout. Keep exposure fixed and motion slow for initial calibration/testing. A calibrated scalar time offset cannot remove row-dependent motion distortion. Quantify readout time and test rotations; replace camera only if measured limits make this configuration unsuitable.

IMU axes remain native sensor XYZ; angular rates use rad/s (17.5 mdps/LSB at +/-500 dps) and acceleration m/s² (0.122 mg/LSB at +/-4g), retaining gravity and bias. Camera pixel coordinates increase right/down; optical z forward. Camera-to-IMU rotation/translation are not inferred from 'flat'/'forward'; they require measured calibration.

Active sensor readback during the wide-mode recording: pixel rate 364,800,000 pixels/s, horizontal blanking 1920, sensor width 1640, height 1232, vertical blanking 3891. Thus line period = (1640+1920)/364800000 = 9.75877 us; first-to-last output row interval ≈ 12.013 ms. The 819-line exposure corresponds to 7992.434 us, consistent with frame metadata. These are timing estimates from driver controls, not an optical measurement of rolling direction or exposure phase. Horizontal and vertical sensor flip controls both read 1 under the libcamera identity transform and camera rotation property 180; preserve pixel geometry and calibrate the resulting image. Evidence: `imx219-active-v4l2.txt`, matching kernel source `kernel-imx219-60ea684.c`, and installed package changelog snapshot.
